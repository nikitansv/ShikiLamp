# Проверка и выпуск ShikiLamp

## Результат проверки 2026-10-03

- 26 наборов Jest, 193 теста — успешно.
- 37 сценариев навигации в Chrome, reduced motion, 27 снимков девяти экранов — без ошибок сценариев и обнаруженного горизонтального переполнения.
- Три варианта загрузки готового bundle и защита от повторной регистрации — успешно.
- `dist/plugin.js` и `docs/ShikiLamp.js` совпадают побайтно.
- Публичные запросы Shikimori: поиск, ID, онгоинги, релизы, анонсы — HTTP 200 с результатами. Браузерная публичная GraphQL-проба также успешна.
- `npm audit` — 0 известных уязвимостей, включая инструменты разработки.
- Реальный телевизор и OAuth-вход аккаунта не проверялись.

## Воспроизводимые проверки

Node.js 22.12+; зависимости устанавливаются через `npm ci`.

```bash
npm run check
npm run test:visual
node scripts/browser-api-check.js
git diff --check
```

- `check`: синтаксис, Jest, сборка, совпадение двух bundle-файлов, загрузка до/после готовности Lampa, позднее появление Lampa, повторная загрузка плагина.
- `test:visual`: браузер с фиксированными данными и моделью навигации Lampa; переходы, Back, фокус, колёсико, dropdown, фильтр, авторизационное окно, отключённая анимация и reduced motion. Снимки девяти экранов при ширине 1920, 1280 и 390 px.
- `browser-api-check`: необязательный живой публичный GraphQL-запрос без токенов. Не проверяет OAuth.
- `npm run test:lampa`: настоящая Lampa из `yumata/lampa`, загрузка плагина через `Lampa.Plugins`, публичные запросы и картинки без подмены host API. Проверяет резервные постеры, каталог/поиск, нативные настройки и Back. Авторизованные экраны проверяются в изолированном состоянии с ответом личного списка из публичных REST-записей; обогащение GraphQL и изображения остаются живыми. Проверяется замена заглушек HTTP 200 на канонические постеры, а не только декодирование картинки. Нужны Git, Chrome и сеть; OAuth-обмен и изменение личных списков не выполняются.
- GitHub Actions выполняет `check` на push/PR и требует актуальные закоммиченные bundle-файлы. Визуальный сценарий запускается отдельно.

## Приёмка на устройстве

Unit-тесты и `test:visual` используют подмену API Lampa. `test:lampa` проверяет реальный браузерный host (проверено на 3.3.5), но перед объявлением совместимости с конкретным телевизором нужно выполнить в его Lampa:

1. Вход по коду, перезапуск приложения, повторное открытие списков после обновления токена.
2. Главная → каталог → карточка → Back: прежняя карточка и прокрутка сохраняются.
3. «Мои списки → В планах»: новые даты сверху; изменение статуса, оценки и эпизодов; удаление и повторное добавление.
4. Пульт: стрелки, Enter, удержание, Back; переключение между фильтром, контентом и меню Lampa.
5. Поиск по названию и числовому ID; «Агент времени 3»; сохранение ручного соответствия.
6. Временное отключение сети и повтор загрузки; импорт ранее экспортированных соответствий без потери локальных записей.

Реальный OAuth-обмен с аккаунтом и приёмка на телевизоре в этой доработке не выполнялись. Публичный OAuth client secret остаётся осознанным ограничением существующей клиентской схемы.

## Публикация

После проверок включить в коммит исходники, тесты и оба файла: `dist/plugin.js`, `docs/ShikiLamp.js`. Опубликовать обычным push. Для установки используется `https://nikitansv.github.io/ShikiLamp/ShikiLamp.js`; при проверке обновления можно добавить `?v=<commit>`.

Если после публикации обнаружена регрессия, восстановить прежнюю версию отдельным revert-коммитом и снова пройти проверки. Не переписывать историю и не удалять пользовательское хранилище Lampa.
