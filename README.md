# ShikiLamp

Плагин для Lampa: каталог и поиск аниме Shikimori, страницы тайтлов, пользовательские списки и сопоставление с TMDB.

## Установка

Добавьте в Lampa как плагин URL:

`https://nikitansv.github.io/ShikiLamp/ShikiLamp.js`

В Lampa откройте **Настройки → Расширения → Добавить плагин**, вставьте адрес и перезапустите приложение. В меню появится **Shikimori**. Плагин рассчитан на Lampa 3; точная совместимость зависит от версии и WebView устройства.

## Возможности

- На главной — «Сейчас на экране» и «Из моих списков», свежие релизы первыми. В «Мои списки → В планах» также действует сортировка по дате выхода.
- Каталог с фильтром, поиск по названию или Shikimori ID. Поиск в Lampa учитывает варианты названий и номер сезона: «Агент времени 3» ищется также как «Агент времени».
- Страницы тайтлов, фильтры каталога, локальный кэш и диагностика соединения.
- Ручное сопоставление Shikimori ↔ TMDB, автоматический подбор через `Lampa.Api.search`, экспорт и импорт сопоставлений. Импорт дополняет записи: при конфликте сохраняет прежнее локальное сопоставление и сообщает число пропущенных записей.
- Вход Shikimori через OAuth или вручную введённый access token; списки пользователя, статусы просмотра, оценка и число просмотренных эпизодов.
- Один раздел настроек **ShikiLamp**: аккаунт, язык названий, видимость меню, размер страницы, плавность переходов и обслуживание. Используется стандартный интерфейс Lampa.
- При недоступном постере TMDB используется исходное изображение Shikimori. Для WebP предусмотрен резервный JPEG; сохранённые ссылки TMDB учитывают текущее зеркало Lampa.

## Ограничения и данные авторизации

В разделе **ShikiLamp → Аккаунт Shikimori** выберите **Войти через Shikimori**, откройте ссылку или QR-код, разрешите доступ и введите полученный код в Lampa. Ручной вход по access token доступен в том же меню. Access/refresh token сохраняются в `Lampa.Storage`; обновление access token выполняется автоматически. Очистка данных Lampa удаляет вход. Сетевые ошибки сами по себе не должны удалять токены.

OAuth client secret включён в клиентский код. Переопределённые client credentials также могут храниться в `Lampa.Storage`. Серверного посредника нет; перенос OAuth на backend отложен. Прогресс эпизодов изменяется вручную в карточке, автоматической синхронизации с плеером нет.

Запросы идут напрямую к Shikimori. Их работа зависит от CORS, сетевых настроек и WebView Lampa; HTTPS-страница не может обращаться к HTTP API из-за mixed content. Поиск TMDB зависит от внутреннего API Lampa. Проверки в браузерном mock не подтверждают работу на реальном телевизоре и его пульте.

## Разработка

Требуется Node.js **22.12 или новее** (требование установленного Puppeteer 25).

```bash
npm ci
npm test
npm run check
npm run test:visual
npm run test:lampa
```

`check` объединяет проверки синтаксиса, тесты, сборку и проверку артефактов. `test:visual` запускает локальный браузерный сценарий с mock-окружением. Ни одна из этих проверок не заменяет запуск в реальной Lampa на целевом устройстве.

`test:lampa` запускает настоящую Lampa из официального репозитория `yumata/lampa` в отдельном браузере, устанавливает текущую сборку через `Lampa.Plugins`, проверяет живой каталог/поиск, превью и нативные настройки. Включает недоступный постер TMDB, отказ WebP с переходом на JPEG, навигацию Back и окно входа. Для авторизованной строки «Из моих списков», каруселей и полного списка использует изолированное тестовое состояние: ответ личного списка заменяется публичными REST-записями реальных тайтлов с изображениями-заглушками HTTP 200, а GraphQL и постеры загружаются с живого Shikimori. Порядок и реальные URL постеров проверяются отдельно от успешной загрузки изображения. Git, браузер и доступ к GitHub/Shikimori должны быть доступны; аккаунт не требуется. Для повторного запуска можно указать `LAMPA_HOST_DIR` с готовым checkout Lampa. Хост и скриншоты сохраняются во временной папке; путь выводится в отчёте. Проверка не выполняет OAuth-обмен и операции с личными списками.

`npm run lint` проверяет синтаксис JavaScript. `npm run test:smoke` проверяет готовую сборку, три порядка загрузки Lampa и повторную загрузку плагина. GitHub Actions запускает `npm run check` на push/PR и проверяет, что собранные файлы совпадают с закоммиченными.

Браузерная проверка использует Chrome из Puppeteer или установленный Google Chrome. Другой путь можно задать через `PUPPETEER_EXECUTABLE_PATH`. Если браузера нет: `npx puppeteer browsers install chrome`. Скриншоты сохраняются во временную папку; её путь выводится в отчёте.

Отдельная сетевая проба `node scripts/browser-api-check.js` обращается к публичному GraphQL Shikimori без авторизации. Её результат зависит от доступности сервиса и CORS; в обязательные локальные проверки она не входит.

Исходники находятся в `src/`, Jest-тесты — в `tests/`, сценарии браузерной проверки — в `scripts/`. Сборка создаёт `dist/plugin.js` и `docs/ShikiLamp.js`.
